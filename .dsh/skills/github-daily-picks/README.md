# 不变量校验脚本（audit.ps1）

用途：一次性检查 github-daily-picks 全套文件的所有硬约束，**替代"靠人肉逐轮检查"**。
只读，不修改任何文件。**共 139 项检查**，覆盖：结构完整性、S 档 12 项口径、限流重试口径、枚举合法性、
落盘顺序依赖、台账 schema、合规红线（防封号）、数量约束、表格文件一致性、三处 12 项字段的**概念名与顺序比对**、
**存量数据只增不减**、**人话层完整性**、**单文件页面与两级分类**、**页面数据无 null 元素**、**页内对比**、**临时检索流程**、**owner 冷却期三处口径一致**、**知识库层完整性（唯一身份 / 无孤儿事件 / 分类枚举）**、以及 **CHANGELOG 与当前文件指纹的对账**（防止改动后记录过期）。

## 怎么跑

在**工作区根目录**执行（两种写法，任选）：

```powershell
# 推荐：在当前会话内执行，任何环境都能用
& ".dsh\skills\github-daily-picks\audit.ps1"

# 也可以：独立进程执行（部分沙箱环境会拒绝启动子进程 pwsh，报"拒绝访问"，那就改用上面那种）
pwsh -File .dsh\skills\github-daily-picks\audit.ps1
```

输出末行是 `结果：N 通过 / M 失败`；`M > 0` 时退出码为 1，便于接进其他流程。

## 什么时候跑

- 改完 `SKILL.md` / `TEMPLATES/daily.md` / `PROMPT-daily.md` / `data/README.md` / `references/*` 之后，**必跑**。
- 任何一项 FAIL，说明文档之间又打架了，**先修文档再跑日报**。
- 脚本本身也是代码，改过它之后请顺手验证一次：故意把某个约束改坏（如把 `S 档 ≤ 3 条` 改成 `≤ 5 条`），
  确认脚本会报 FAIL，再改回来 —— **一个永远全绿的检查等于没有检查**。

## 它查不了什么（重要）

本脚本只校验**文本层面的内部一致性**，验证不了功能正确性：

- 检索式能否真的返回结果（需要实跑）
- 模型执行时会不会真遵守这些约束（需要实跑）
- 评分排序结果是否合理（需要人工看日报）
- `.univer` 表格能否被打开（文件尚未生成）
- 日报是否好读（需要你本人判断）

**这四项只有实跑一次才能验证。**
