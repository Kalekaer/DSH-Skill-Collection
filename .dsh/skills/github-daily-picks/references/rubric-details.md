# 热度归一化与冷启动算例

> 本文件**不定义权重**。权重、硬排除、分档一律以 `RUBRIC.md` 为准；本文件只是把 `RUBRIC.md` 中「热度 20 分」这一项展开成可计算的细则。

## 1. 归一化口径

三项指标各自 min-max 归一化到 `0–1`（分母只取**本次候选池**的最大值/最小值，候选池变了就重算，不跨天比较）：

```
stars_norm = (stars − min_stars) / (max_stars − min_stars)
forks_norm = (forks − min_forks) / (max_forks − min_forks)
trend_norm = (Δstars/天 − min_trend) / (max_trend − min_trend)
```

合并为热度分量（满分 20）：

```
热度 = 20 × (0.45 × trend_norm + 0.35 × stars_norm + 0.20 × forks_norm)
```

**没有增量数据就没有 `trend_norm`** —— 此时不要把该项记 0，走下面的冷启动规则。

## 2. 冷启动 / stale 规则（重要）

| 情形 | 判定 | 处理 |
|---|---|---|
| 快照目录只有 1 份 | 无间隔，无 `Δstars` | 走冷启动 |
| 最近快照与今日间隔 > 3 天 | 标 `stale` | 走冷启动 |
| 候选仓库不在任何历史快照里 | 无基线 | 走冷启动，且**不得**用别的仓库的增速代替 |

**冷启动时**：

1. `trend_norm` **不参与排序**，其权重（20 × 0.45 = **9 分**）**按比例并入「实用性」**：

```
实用性_冷启动 = 35 + 9 = 44 分（其余维度不变，总分仍为 100）
```

2. 可用 `est_daily = stars ÷ (今日 − created_at 的天数)` 作临时替代值，**必须标注「估算」**，且**只用于展示、不用于排序**。
3. 在运行日志写明「本次为冷启动，热度按实用性加权」。

> 实测背景：`data/runs/2026-10-11.md` 首日即为此情形，8 条推荐的增速全部标注为 `est.`。从有第二份快照起改用真实差值。

## 3. 算例

候选池 4 个仓库，某日快照对比后：

| 仓库 | stars | forks | Δstars/天 |
|---|---|---|---|
| A | 12000 | 900 | 420 |
| B | 3000 | 210 | 150 |
| C | 800 | 40 | 30 |
| D | 250 | 12 | 0（无基线） |

归一化（min/max 取自本池）：

- `trend_norm`：A = (420−0)/(420−0) = **1.00**；B = **0.36**；C = **0.07**；D **冷启动，不参与**
- `stars_norm`：A = **1.00**；B = (3000−250)/(12000−250) = **0.23**；C = **0.05**；D = **0.00**
- `forks_norm`：A = **1.00**；B = **0.22**；C = **0.03**；D = **0.00**

**A**：热度 = 20 × (0.45×1.00 + 0.35×1.00 + 0.20×1.00) = **20.0**
**B**：热度 = 20 × (0.45×0.36 + 0.35×0.23 + 0.20×0.22) = 20 × 0.288 = **5.8**
**C**：热度 = 20 × (0.45×0.07 + 0.35×0.05 + 0.20×0.03) = 20 × 0.055 = **1.1**
**D**：热度不计算，`实用性` 按 44 分口径评，并在条目里标「增速：无基线（估算 X/天）」。

注意 **C 与 D 的对比**：C 增速只有 30/天但确实在涨，D 只是没有基线——这正是不能把 `trend_norm` 记 0 的原因，否则 D 会被系统性低估，而新库恰恰最容易是 D 型。

## 4. 与「实用性」的关系

- 热度再高，`实用性` 低仍然进不了日报：`RUBRIC.md` 的分档看总分，而实用性占 35（冷启动 44），是最大项。
- 单独的可执行产物（CLI / release 包 / 一键安装）优先于"框架"和"资源列表"，这条不受热度加分影响。
- 反例：3 万 star 的 `awesome-*` 合集热度可以打满 20，但命中 `RUBRIC.md` 第 1 节的硬排除，**直接淘汰，不参与打分**。
