### 2. demo/portkiller · S 档 · Rust · 890★（+15/天）

1. **项目名**：demo/portkiller
2. **一句话定位**：这是一个给后端开发者用的命令行小工具，能帮你一条命令找到并杀掉占用某个端口的进程。
3. **30 秒判断**：它是单文件 CLI ｜ 解决「端口被占用」这个天天遇到的小麻烦 ｜ 适合常起本地服务的人 ｜ 不适合需要图形界面的新手 ｜ 风险：中 ｜ 行动：试玩。
4. **基本信息**：github.com/demo/portkiller ｜ 三人团队 ｜ Rust ｜ Apache-2.0 ｜ ★890 ｜ 6 天前更新 ｜ 未归档 ｜ 不需要密钥，不付费。
5. **分类标签**：开发 / CLI / 提效 / 活跃 / 开箱即用 / 中。
6. **它到底干啥**：像「给端口做的一次精准拆弹」。痛点是：本地开发时 3000 端口被占用，你只知道有东西占着，但要 `netstat` 加 `taskkill` 翻半天。核心功能：① 按端口列出占用进程；② 交互式确认后结束；③ 支持批量端口。典型场景：重启前端 dev server、清掉僵尸进程、CI 里收尾。**它不做什么**：不做系统级服务管理，不自动杀进程（必须确认）。
7. **怎么用**（已核实 README）：
   ```bash
   cargo install portkiller      # 或下载 release 里的单文件二进制
   portkiller 3000               # 列出占用者
   portkiller 3000 --kill        # 确认后结束
   ```
   本机可用；无需账号与密钥。
8. **亮点**：一个 Rust 单文件，启动毫秒级，比记忆 `netstat` 参数省事；相比同类缺：没有 GUI，不熟悉命令行的要适应一下。
9. **风险与注意**：安全——**会终止进程**，可能丢掉未保存的工作，是本条唯一真实风险点，不需要 root（杀自己启动的进程即可）；法律——Apache-2.0，可商用，注意保留 NOTICE；隐私——无遥测；维护——6 天前有提交，过去 30 天有 release；成本——零；使用——建议先不带 `--kill` 跑一遍确认；供应链——依赖已 pin，有 `Cargo.lock`；社区——fork/star = 0.11，正常。
10. **适合谁 / 不适合谁**：适合每天在本地起服务的开发者；不适合不敢碰命令行、或机器上有共享服务的人。
11. **学习成本**：看懂 1 分钟 ｜ 跑起来 3 分钟 ｜ 用熟 10 分钟。
12. **总结**：风险只在「杀进程」这一步，带 `--kill` 前看一眼列表就行 —— 建议试玩。
